ЗАДАЧА ФАЗЫ 7 — независимый аудит результата и документация. Ты не автор кода: твоя цель — найти расхождения, а не защитить решения.

1. АУДИТ СООТВЕТСТВИЯ
   - Сверь фактическое состояние с `docs/plans/decisions.md`: стиль page-слоя, конфигурация, версии, структура. Каждое расхождение — в список с файлом и строкой.
   - Проверь scope creep: есть ли изменения вне семи пунктов задания (лишние зависимости, рефакторинги, «улучшения»).
   - Проверь дрейф версий: Selenide/JUnit/Gradle/Java не изменились без записи в `decisions.md`.

2. БЕЗОПАСНОСТЬ
   - `git grep -inE "token|chat_id|password|secret|api[_-]?key"` по репозиторию: значения, похожие на реальные, — блокер.
   - Просмотри workflow и `Jenkinsfile`: секреты только из secrets/credentials, нет `echo`/`set -x` рядом с ними.
   - Проверь, что в логах последних прогонов (GHA и Jenkins) нет токена.
   - Проверь `.gitignore`: `build/`, `.gradle/`, `.idea/`, локальные отчёты не должны попадать в индекс.

3. ВОСПРОИЗВОДИМОСТЬ
   - Выполни с чистого состояния: `./gradlew clean test -Dselenide.headless=true`.
   - Выполни команду генерации отчёта ровно так, как она записана в документации. Любая «почти работает» формулировка — дефект документации.
   - Прогони тесты дважды подряд: зафиксируй флаки и гипотезы (captcha, динамическая разметка, таймауты).
   - Проверь, что `-DbaseUrl`/env-переопределения работают так, как описано, и что дефолты не «залипают».

4. README
   - Добавь/обнови раздел в `README.md`:
     - как запустить локально (headed/headless), какие нужны JDK/браузер;
     - таблица конфигурации: ключ → `-D` → env → default;
     - как сгенерировать и открыть Allure-отчёт (одна команда);
     - ссылки на GHA workflow и опубликованный отчёт, как получить доступ к Jenkins;
     - какие секреты нужны и где их задавать (без значений);
     - структура проекта: `tests/`, `pages/`, `config/`.
   - Команды в README должны быть скопированы из реально проверенных, а не написаны «по памяти».

5. ИТОГОВЫЙ ОТЧЁТ
   - Таблица: требование задания → статус (готово/частично/нет) → доказательство (файл, run, ссылка).
   - Найденные дефекты: критичные (секреты, неработающие команды, красный CI) → исправить сразу; некритичные → список с приоритетом, без правок.
   - Остаточные риски и что бы ты сделал следующим занятием (параллельность, кросс-браузерность, стабильный тестовый стенд).
   - Обнови `decisions.md`: итоговый статус фаз, известные ограничения.

ОГРАНИЧЕНИЯ
- Не переписывай архитектуру «как правильнее»: это занятие завершено, замечания — в список.
- Код меняй только при критичных дефектах (секрет, сломанная команда, красный CI) и перечисляй каждую правку.
- Не коммить.

DoD ФАЗЫ
- Ноль секретов в репозитории и логах.
- `./gradlew clean test -Dselenide.headless=true` зелёный, два прогона подряд.
- README позволяет новому человеку повторить запуск и открыть отчёт без подсказок.
- Итоговая таблица «требование → статус → доказательство» заполнена.
