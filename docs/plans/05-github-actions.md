ЗАДАЧА ФАЗЫ 4 — запуск тестов в GitHub Actions с браузером/драйвером в раннере и публикацией Allure-отчёта.

ПРЕДУСЛОВИЯ
- Локально зелёный `./gradlew test -Dselenide.headless=true`.
- Известна команда генерации отчёта (фаза 3) и способ проброса `-D` (фаза 1).
- Прочитай `decisions.md`: разделы «Версии» и «Артефакты».

1. WORKFLOW
   - Файл `.github/workflows/tests.yml`. Триггеры: `push`, `pull_request`, `workflow_dispatch`.
   - `concurrency` по ref с `cancel-in-progress: true`, разумный `timeout-minutes` (например 30), минимальные `permissions` (для публикации отчёта — `contents: write`, если используется gh-pages).
   - Шаги: checkout → JDK (Temurin 25) с кэшем Gradle → браузер/драйвер → прогон тестов headless → выгрузка `allure-results` (`if: always()`) → генерация HTML → публикация → job summary.
   - Прогон — тем же способом, что локально (`./gradlew test` + те же `-D`/env). Не заводи второй параллельный способ конфигурации.

2. БРАУЗЕР И ДРАЙВЕР (обоснуй выбор)
   - Вариант A: Selenium Manager (Selenide 7 сам скачивает драйвер) — меньше шагов, но зависимость от сети/зеркал на каждом раннере.
   - Вариант B: явная установка Chrome/драйвера action'ом — детерминированнее, но добавляет шаг и версии.
   - Выбери один, обоснуй в отчёте и запиши в `decisions.md`. Проверь актуальные названия и мажорные версии actions по официальной документации; не выдумывай.
   - Убедись, что `headless` включён именно в CI, а локально по умолчанию остаётся headed.

3. ПУБЛИКАЦИЯ ОТЧЁТА
   - HTML-отчёт публикуй на GitHub Pages (или gh-pages). Ссылка должна открываться без авторизации.
   - `allure-results` выгружай артефактом всегда, даже при падении тестов — иначе разбор невозможен.
   - В `GITHUB_STEP_SUMMARY` добавь: статус, количество тестов, ссылку на отчёт.
   - Не публикуй отчёт для PR из форков с секретами — здесь секретов ещё нет, но структуру заложи.

4. ПРОВЕРКА
   - Сделай реальный push (или `workflow_dispatch`) и дождись завершения.
   - Проверь: job зелёный, артефакт скачивается, ссылка на отчёт открывается в приватном окне браузера.
   - Проверь второй прогон: кэш Gradle работает, время не растёт.
   - Если тест упал по captcha/rate-limit — не «чини» workflow: зафиксируй риск и предложи меру (переопределяемый `baseUrl`, тег smoke, отдельный таргет для CI).

5. ОТЧЁТ
   - Файл workflow + `git diff --stat`.
   - Ссылка на успешный run и на отчёт.
   - Что именно выбрано для драйвера и почему.
   - Что переиспользуется в фазе 5 (имя артефакта, URL отчёта, статус job).
   - Обнови `decisions.md`: действия и их версии, URL отчёта, статус фазы.

ОГРАНИЧЕНИЯ
- Не добавляй Telegram-уведомления — это фаза 5.
- Не меняй тесты и build-логику ради «позеленить» CI.
- Не добавляй секреты.
- Не коммить, пока не попросят (но run требует push — уточни у студента, как публиковать: push в свою ветку/форк).

DoD ФАЗЫ
- Workflow в репозитории, зелёный run.
- `allure-results` — артефакт, HTML-отчёт доступен по ссылке.
- Соответствие «локально = CI»: одинаковые команды и ключи конфигурации.
