# План занятия: getting-started-java → полный учебный CI-контур

Комплект промптов для курса qa.guru/ai-first. Один файл = одна фаза = одна сессия агента.
Цель: из репозитория с одним тестом получить воспроизводимый контур «TestBase → тесты → PageObject → Allure 3 → GitHub Actions → Telegram → Jenkins».

## Состав

| Файл | Фаза | Результат | Модель (reasoning) |
|---|---|---|---|
| `00-master-prompt.md` | Контекст | Роль, правила, глобальный DoD | — |
| `01-audit.md` | 0. Аудит | Заполненный `decisions.md`, риски, структура | Claude Opus 5.5 / Opus 5 (high) или GPT-5.1 (high) |
| `02-testbase.md` | 1. TestBase + конфиг | `TestBase`, конфиг, проброс `-D` | Claude Sonnet 5 (high) или GPT-5.1 Codex (high) |
| `03-tests-pageobject.md` | 2. Тесты + PageObject | 3–4 теста, page-слой | Claude Sonnet 5 (high) / GPT-5.1 Codex (high) |
| `04-allure3.md` | 3. Allure Report 3 | Результаты + HTML-отчёт | Claude Sonnet 5.5 (high) или Gemini 3.1 Pro (high) |
| `05-github-actions.md` | 4. GitHub Actions | Workflow с браузером и публикацией | GPT-5.1 (medium) или Gemini 3.5 Flash (medium) |

| `decisions.md` | Журнал | Единый источник истины по решениям | Заполняется по ходу |

## Как пользоваться

1. Откройте **новую сессию** агента (фаза = сессия, так контекст не разрастается).
2. Приложите файл `00-master-prompt.md` целиком (это роль и правила) **или** скопируйте его в первое сообщение.
3. Скопируйте содержимое нужного фазового файла ниже разделителя `---` и отправьте агенту.
4. Агент обязан обновить `decisions.md`. Не переходите к следующей фазе, пока не выполнен DoD текущей.
5. Фазу 7 выполняйте **другой моделью**, чем писали код: смысл — независимое ревью.

## Маршрутизация моделей (кратко)

- **Архитектура, совместимости, риски** → Opus-класс / GPT-5.1 high. Дорого, но здесь ошибка стоит всей практики.
- **Java-код и page-слой** → Sonnet 5 / GPT-5.1 Codex high. Лучший баланс «многофайловые правки + следование конвенциям».
- **YAML, CI-обвязка, уведомления** → GPT-5.1 medium / Gemini Flash / Haiku. Быстро и дешево, сложных решений нет.
- **Финальное ревью** → модель другого вендора, чем у автора кода.
- Дешёвые модели не ставить на PageObject и Allure: экономия на токенах компенсируется кругами переделок.

## Правила гигиены

- `decisions.md` — единственный источник истины. Если код и `decisions.md` расходятся, побеждает `decisions.md` до явного пересмотра.
- Секреты (Telegram, credentials) — только в GitHub Secrets / Jenkins Credentials. В промптах и репозитории их быть не должно.
- Версии Selenide/JUnit/Gradle/Java не меняются без отдельного решения, записанного в `decisions.md`.
- Никаких `Thread.sleep` и retry-хаков для «стабилизации». Флак разбирается гипотезой и мерой.
- Один коммит на фазу — по явной команде, не автоматически.

## Риски, заложенные в план

| Риск | Где закрывается |
|---|---|
| `allure-junit5` может не поддерживать JUnit 6.1.x | Фаза 0 (вердикт) и фаза 3 (решение) |
| Allure 3 — новый CLI, Jenkins-плагин может не поддерживать | Фазы 0, 3, 6 |
| `github.com/search` в CI: rate-limit/captcha → флак | Фазы 0, 2, 4 |
| Gradle не форвардит `-D` в test JVM | Фаза 1 (обязательная проверка) |
| Секреты Telegram в логах | Фазы 5, 7 |

## Что сознательно вне scope

Параллельный запуск тестов, кросс-браузерная матрица, Selenium Grid как отдельный стенд, тест-менеджмент (TestOps/TestRail), контейнеризация локальной разработки. Если студент захочет — это отдельные занятия, а не «попутно».
