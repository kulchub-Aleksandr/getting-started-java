ЗАДАЧА ФАЗЫ 0 — только аудит и решения. Код не пиши, зависимости не меняй, ничего не рефактори.

1. ПОДТВЕРДИ ФАКТЫ
   - `git status --short`, `git log --oneline -5`, `git remote -v`.
   - Прочитай `build.gradle`, `gradle/wrapper/gradle-wrapper.properties`, `src/test/java/SearchTests.java`.
   - Перечисли, чего в репозитории нет (TestBase, pages, Allure, CI).
   - Выведи фактическую версию Java (`java -version`).

2. ЗАФИКСИРУЙ BASELINE
   - Запусти `./gradlew test` (headed, локальный Chrome).
   - Если тест падает — не чини. Зафиксируй как риск: текст ошибки, гипотеза (сеть, captcha, локатор, версия браузера).
   - Результат внеси в `decisions.md`, раздел «Риски».

3. ПРОВЕРЬ СОВМЕСТИМОСТЬ (каждый пункт: вердикт + ссылка на официальный источник)
   - `allure-junit5` (или актуальный адаптер) × JUnit Jupiter 6.1.3: поддерживается? какая версия адаптера?
   - `allure-selenide` (скриншоты/шаги) × Allure 3: актуален ли модуль или интеграция делается иначе?
   - Allure Report 3: способ установки CLI (npm/бинарник/другое), команды generate/open, требования к `allure-results`.
   - Selenide 7.18.2 × Java 25: известные ограничения?
   - Jenkins Allure plugin × Allure 3: поддерживается? если нет — какие альтернативы (CLI + publishHTML/archive)?
   - GitHub Actions: актуальные способы поставить Chrome и драйвер в `ubuntu-latest`; сравнение «Selenium Manager» vs «setup-action».
   - Формат ответа: таблица `Вопрос | Вердикт (да/нет/требует проверки) | Источник | Влияние на план`.
   - Если источник не найден — пиши «требует проверки» и предложи, как проверить дешёво (пробный прогон, `npm view`, Maven Central).

4. ЗАДАЙ ВОПРОСЫ ПО СТИЛЮ (S1–S12) С ДЕФОЛТАМИ
   - Предложи рекомендуемый вариант для каждого пункта и короткое обоснование.
   - Не начинай фазу 1, пока ответы не зафиксированы.

5. ЗАПОЛНИ `docs/plans/decisions.md`
   - S1–S12: выбранные решения.
   - Версии: что зафиксировано, что «требует проверки».
   - Риски: вероятность, влияние, мера, статус.
   - Целевая структура файлов с учётом S1 (например `tests/`, `pages/`, `config/`).
   - Секреты: только имена, без значений.

6. ОТЧЁТ
   - Факты, таблица совместимости, вопросы, риски, целевая структура, что дальше (фаза 1).
   - Явно напиши, какие пункты плана придётся изменить из-за findings (например «Allure adapter не поддерживает JUnit 6 → на фазе 3 нужно решение о понижении JUnit»).

ОГРАНИЧЕНИЯ
- Ни одной правки в `src/`, `build.gradle`, wrapper.
- Не устанавливай глобальные пакеты без спроса; если нужен `npm view`/`curl` для проверки версий — это допустимо, но без изменения системы.
- Не коммить.

DoD ФАЗЫ
- `git status --short` не содержит изменений в `src/` и `build.gradle`.
- В `decisions.md` заполнены разделы 1–4.
- Для каждого утверждения о совместимости есть ссылка или явная пометка «требует проверки».
